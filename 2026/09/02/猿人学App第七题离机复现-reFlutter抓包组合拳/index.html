猿人学 App 第七题「flutter」离机复现：reFlutter 引擎替换 + adb reverse 抓包组合拳

本文最后更新于：2026年9月2日 上午

[猿人学 App 逆向系列]第七题「衣带渐宽终不悔【flutter】」。这是一个 Flutter 应用，取数逻辑在 Dart AOT（libapp.so），用 Flutter 自带的 BoringSSL 走 HTTPS——Flutter 抓包是出了名的难。
本文记录踩过的坑，以及最终跑通的一套组合拳：reFlutter 产出关 pinning 的引擎 → root 只替换 libflutter.so 进原版 app（避开重打包崩溃）→ adb reverse 解决跨网段 → mitmdump 反向代理抓明文。

一、为什么 Flutter 难抓

ChallengeSevenFragment 里就是个 FlutterView + FlutterEngine，真正的请求逻辑在 Dart 编译成的 libapp.so（AOT 机器码）。联网用的是 Flutter 静态链接的 BoringSSL（在 libflutter.so 里），它：

  • 不走系统代理（设置系统 proxy 没用）；
  • 用自己打包的根证书（系统装 mitm CA 也不认）；
  • 符号全剥离：libflutter.so 10MB，只有 1 个导出符号，SSL_read/SSL_write 都没符号。

所以常规的”设代理 + 装证书”抓不到，得从 native 层想办法。

二、走不通的路：直接 hook SSL_write

先试直接在 libflutter 里定位 SSL_write 来 hook 明文。思路是靠 BoringSSL 保留的 __FILE__ 断言串（ssl_lib.cc/s3_pkt.cc 等）做 xref，再回溯函数起点。

结果很不稳：libflutter 把 BoringSSL 和 Skia/Dart VM 代码高度交织，capstone 在 5MB 代码段反复失步、函数边界回溯落到 Skia 渲染函数上，frida 还拒绝 hook 错误地址。握手阶段的证书（*.python-spider.com、pki.goog）能抓到，但应用数据的 SSL_write 始终定位不准。这条路对这种优化过的 release 引擎不友好。

三、reFlutter：拿到关 pinning 的引擎

换思路，用专门工具 reFlutter：

reFlutter 按 SnapshotHash 匹配 Flutter 引擎版本，换上它预编译好的、关掉 SSL pinning 且把流量导向指定 IP 的引擎，产出 release.RE.apk。

四、关键一招：只替换 libflutter.so，不重打包

直接装 reFlutter 产出的 release.RE.apk 会启动即崩：

这是 apktool 重打包丢了 FileProvider 的 meta-data（重打包产物 bug，不是 app 自检）。

破法：reFlutter 换的是”同版本、已关 pinning 的引擎”——那我只要这块 libflutter.so，不要它重打包的其它部分。用 root 把 patched 的 libflutter.so 覆盖进原版 app 的 native 目录即可：

原版 app 的签名、manifest、其它 so 全不动 → 不触发 FileProvider 崩溃，Dart 快照（libapp.so）和 reFlutter 的同版本引擎兼容 → 正常跑，但 SSL 已被关校验、流量已被导向代理。

reFlutter 把流量导向我给的 IP:8083，但手机(172.16.5.x)和开发机(172.16.4.x)跨网段、ping 不通。用 adb reverse 打通：

开第七题——明文出来了。

六、抓到的请求 + 签名分析

  • content = "页码:毫秒"；
  • sign 是 SHA256（64 位 hex，libapp.so 里能看到 _Sha256Sink、package:crypto/src/sha256.dart）。

但 sign 不是简单的 SHA256(content)——带一个 Dart 里嵌的密钥/盐。静态穷举 libapp.so 全部字符串（含 CJK）当盐、把候选当 hex/base64 key 做 HMAC、内存里扫”含 content 的更长串”（哈希输入是瞬时 Uint8List，扫不到）、找 SHA256 的 K 表（Dart 整数是 tagged、非裸 uint32）——都没能完全还原。要拿到纯离线签名，得上 Blutter 之类工具反编译 Dart AOT 快照。

不过抓包既然已通，取数就不受阻了：滚动加载全部 100 页，mitm 抓齐每页响应（每页 10 个数），求和即得答案，提交通关。

小结

第七题的难点全在”怎么看到 Flutter 的 HTTPS 明文“。踩坑后跑通的这套组合拳值得记：

  1. reFlutter 出关 pinning 的同版本引擎；
  2. 只 root 替换 libflutter.so 进原版 app——绕开重打包的 FileProvider 崩溃、也不动签名；
  3. adb reverse 打通跨网段，mitmdump reverse 模式 抓明文（避开 Windows 透明模式的管理员权限）。

签名侧 SHA256(content + Dart内嵌密钥) 的完全离线还原留待 Blutter——但对”取数通关”而言，抓包打通就够了。这也是逆向里常见的取舍：能抓到就未必要死磕纯算法还原。
