猿人学 App 第十一、十三题离机复现：upx 脱壳与「封设备」的纯 Python 还原

本文最后更新于：2026年9月1日 下午

继[第四、五题]之后，再记两道猿人学 App 闯关题的离机复现。这两题都是”分页数字列表求和”，反爬点都藏在 native：

  • 第十三题「东风夜放花千树【封设备】」：请求带 native 生成的 device_id，服务器按其中的 MAC 段当”设备身份”限流。破解后把整套 device_id 算法反成了一张 16 项查表的纯 Python。
  • 第十一题「学诗谩有惊人句【upx壳】」：请求参数 data 由 UPX 加壳的 libeleven.so 生成。内存 dump 脱壳 + Frida 取样后，发现它不过是 {page}:{时间戳} 的自定义 Base64。

一、第十三题：device_id 的「封设备」

1.1 请求模型（静态反编译）

ChallengeThirteenFragment 翻页逻辑很直白，device_id 来自 native：

  • 取数端点：POST /api/app13，表单 device_id + page（登录后拦截器附加 token）。
  • 提交端点：POST /challenge/api/app_check，id=40 + anw + token。

1.2 用 Unicorn 模拟 getDeviceId

libthirteen.so 被 goron/OLLVM 混淆、方法名运行时解密，与第四题同法用 Unicorn 忠实模拟：

  1. 定位函数：模拟 JNI_OnLoad，在 RegisterNatives 处截获方法表 → getDeviceId @ 0x47944。
  2. JNI/libc 打桩：JNIEnv 函数表逐槽分派；实现 clock_gettime、AArch64 变参 __vsnprintf_chk、strftime、random_device 等。
  3. NETLINK 应答：getDeviceId 会 socket(AF_NETLINK)+sendto+recvfrom 向内核发 RTM_GETLINK/RTM_GETADDR 读本机网卡 MAC/IP——它不是连服务器！脚本伪造 netlink dump 应答让它跑完。

1.3 单变量对照：锁定「设备身份」

固定时间戳、逐个改动输入，逐字符 diff 得出 device_id（80 位大写 hex = 40 字节）的结构：

变量 是否影响 device_id
毫秒时间戳 ✅ 改变时间戳区 6 位
本机 MAC ✅ 改变中段 38 位 = 设备身份
random_device ❌ 调用了但不进 id（反模拟诱饵）

⚠️ 踩坑：最初卡在 page≥2 恒被封，根因是**模拟器 netlink 应答把 MAC 写死成 02:00:00:00:00:00**——所有 id 在服务器眼里是同一台设备。把 MAC 接进 netlink 应答、每次随机化后立即畅通。

1.4 「封设备」真相与破解

服务器把 device_id 里的 MAC 段当设备身份，每设备约 2 次请求后封（设备号已被封锁）。破解 = 每翻一页现造一个随机 MAC 的 device_id，服务器即视为新设备。共 100 页。

1.5 反成纯 Python（免 so / Unicorn）

关键发现让纯 Python 成为可能：

  1. 各段独立无扩散，MAC 第 i 字节只影响第 i 组；
  2. 6 组共享同一个 delta 函数（只是各组常量基 BASE_i 不同）；
  3. 服务器逐字节 checksum 校验（随机 UUID 一律 check request），但用真实算法换 MAC 得到的仍是合法 id；
  4. 时间戳区仅 16bit，服务器不校验时间戳新鲜度 → 固定一张旧模板即可。

**答案 = 5075506**，提交 app_check id=40 通过。

二、第十一题：upx 壳

2.1 请求模型

ChallengeElevenFragment：POST /api/app11，单字段 data = native String data(int page)（libeleven.so）；提交 id=38。

2.2 识别 upx 壳

磁盘上的 libeleven.so：.text 全是 udf、节内容不可读、含 UPX! 与 $Info: This file is packed，但 UPX0/UPX1 节名被抹掉（防 upx -d）。

试图离线 Unicorn 脱壳：跑 DT_INIT 自解密 stub 时，它疯狂 mmap（svc 0xDE）约 90 万次、疑似反模拟死循环——不实际。改走内存 dump。

三、两题的共同套路

第十三题「封设备」 第十一题「upx 壳」
反爬本质 device_id 里嵌 MAC，按设备限流 参数生成逻辑藏进加壳 native
native 处理 goron 混淆 → Unicorn 忠实模拟 UPX 加壳 → 内存 dump 脱壳
取样手段 模拟器跑 getDeviceId Frida 主动调用 data()
最终算法 MAC 6 组 XOR 16 项查表 {page}:{ts} 自定义 Base64
服务器校验 device_id 全字节 checksum，但不验时间戳新鲜度 不验时间戳新鲜度
结果 纯 Python 免设备 纯 Python 免设备

两题殊途同归：native 只是把一个并不复杂的算法藏起来——一个靠混淆、一个靠加壳。把真实代码”跑起来或 dump 出来”拿到样本后，用单变量对照 / 解码定位算法，最后都能反成零依赖的纯 Python。

  • 第十三题共 100 页，答案 5075506；
  • 第十一题共 100 页，答案 5056355。
